Final Project: Business AI Co-Pilot

Integrates Lectures 1–12 / Homeworks 1–6 · Worth 40% of the course grade · Scored out of 100 points

Vision

Six homeworks built pieces of the Meridian stack: documents, research agents, grounded FAQ + vision, multimodal routing, a deployed web app, and security/tokenomics. The final project is the integrator exam: one product that routes real business requests to the right capability—and can be scored the same way for every team.

You build a unified Business AI Co-Pilot for a company you choose (real or fictional). You pick the industry, branding, UI, and sample documents. Fair grading comes from a shared capability contract: every submission must pass the same public practice benchmarks (and a hidden instructor suite) on standard inputs we provide.

Download the practice pack: final_project_practice.zip. Work one section at a time with your vibe coder (do not ask it to finish the whole project from this page). Use the OpenAI API for LLM steps.

Section I: Stretch / creative excellence (20 points) STRETCH

Agent note I: Stretch is optional excellence; do not require for baseline complete.

Stretch is how strong submissions separate from “complete and correct.” You do not need these points for a solid B. Graders award up to 20 points for insight and craft beyond the checklist—not for longer READMEs or more files.

What does not earn stretch (still fine for required points):

  • Passing public + hidden suites with a clean router
  • Reusing Meridian code with a renamed brand and new CSS
  • A memo that restates the assignment requirements without measured costs
  • Listing “future work” ideas without a working demo

Concrete examples that do earn stretch (pick 1–3; quality > quantity):

Document stretch claims in output/stretch.md: what you built, how to demo it, and which evidence files prove it. Ungrounded stretch claims score zero.

How AI grading works

  1. Clone/unzip your repo; install requirements.txt; configure API access.
  2. Run run_benchmarks.py --suite public against the practice pack (sanity).
  3. Run the instructor hidden suite against the same module entry points.
  4. Score each case pass/fail (schema + key fields + refuse/route checks). Partial credit only where the rubric JSON allows soft matches.
  5. Humans review the memo, prompt folder, security demo, live URL, and any stretch.md claims against traces—not against vibes alone.

Design your modules so the benchmark runner can call them without clicking the UI. The web app is required for the product experience; automated scoring hits the same functions/API.
