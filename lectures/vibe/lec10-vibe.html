Lecture 10: Multi-Agent Systems

← Slides All lectures · In-class vibe coding

Scenario

Today you build a multi-agent chat app that answers questions about the Harry Potter books. You ask your questions to a boss agent who then delegates hard questions to seven specialist agents (one per novel). Each specialist answers from passages retrieved out of a local database of the books.

A frontend for the app is provided for you already, along with a database of the books. In class you will build the multi-agent backend system.

Task

Clone the starter repo. It contains the React front end and an empty Python FastAPI backend. Build the PydanticAI multi-agent system where the boss agent can take a user question, delegate the work to the specialist worker agents, and synthesize their results for the user.

Pieces you’ll end up with:

  • Boss agent — chats with you; tool to delegate work to a book specialist
  • Worker agents — one per book; retrieve chunks from the database, then do the delegated task
  • Event queue — each agent action goes on a queue so the front end can show live progress

- PORTKEY_API_KEY=... in a .env (python-dotenv); may be in this folder OR the parent — load both

Goal
A boss agent chats with the user. For book facts it uses a tool that delegates to a book specialist (worker) for book_number 1–7. Each specialist pulls relevant text chunks from harrypotter.db for its book only, answers from that evidence, and returns a reply. While this runs, push live events onto an asyncio.Queue so /api/chat/stream can SSE them to the dashboard.

What main.py imports (implement these)
1) models.py
- BOOK_CATALOG: list of 7 dicts (book_number 1–7) with title, short, specialty blurb, accent color, house_hint — used by /api/roster
- ChatRequest: message: str
- ChatResponse: answer, delegations list, optional trace, boss_name
- Delegation: agent, book_number, book_title, question, reply, status (pending|running|done|error)

2) retrieval.py — helpers so specialists never load a whole novel into the prompt
- list_books() — metadata rows for health/roster
- get_book_meta(book_number) — title and counts for one book
- retrieve_chunks(book_number, question) — keyword-score overlapping chunks from that book’s text; cap total evidence (~40k chars)
- format_evidence(chunks) — join chunks into a prompt-ready string

3) agents/config.py
- BOSS_NAME (friendly display string), MODEL_NAME default gpt-6-astra
- require_api_key(), build_model() using AsyncOpenAI + Portkey base URL (same pattern as earlier lectures)

4) agents/boss.py + prompts/boss.md
- PydanticAI Agent with async tool ask_book_specialist(book_number: int, question: str)
- Tool calls the matching specialist, waits, returns agent / book_number / book_title / reply / status
- BossDeps holds an asyncio.Queue + delegations list; emit(event_type, **data) puts {"type", "data"}
- Emit boss_thinking when starting; specialist_started / specialist_done around each tool call
- run_boss_chat_stream(message) yields those events, then a final (or error) event whose data matches ChatResponse
- run_boss_chat(message) wraps the stream and returns the final dict
- Boss may call the tool multiple times for cross-book questions; synthesize from specialist reports only — do not invent book facts

5) agents/specialists.py + prompts/specialist.md
- run_specialist(book_number, question) retrieves chunks, builds instructions from specialist.md + evidence, runs a PydanticAI agent, returns reply + status (+ passages_used)
- Answer only from retrieved passages; if evidence is thin, say so honestly

SSE event types the UI expects: boss_thinking, specialist_started, specialist_done, final, error

How to run / test
1) Backend: cd backend → venv + pip install -r requirements.txt → uvicorn main:app --reload --host 127.0.0.1 --port 8000
2) Frontend: cd frontend → npm install → npm run dev → http://127.0.0.1:5173 (proxies /api to 8000)
3) Ask something cross-book (e.g. Horcruxes across the series). Confirm specialists light up on the dashboard and the final answer cites what they found.
