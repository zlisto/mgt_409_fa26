Lecture 10: Agent Orchestration

← Slides All lectures · 40 minutes in class

40-minute lab. If you are still polishing the server at minute 10, skip the stretch and jump to the orchestrator. 0–8 server · 8–13 catalog · 13–23 loop · 23–32 refuse · 32–37 eval · 37–40 log
In-class goal: Build a tiny MCP server plus an orchestrator that calls more than one tool, writes a tool trace, and refuses when two tools disagree. This is a coffee-cart toy — not Homework 5.

If the menu promises Sunday brunch and the hours file says “closed Sunday,” your agent is not a diplomat. It is a referee.

Work in a new folder lec10_vibe/. Use the OpenAI API the same way you do for homework. Do not paste the Peabody zip into this session.

Step 1 Toy MCP server 0–8 min

Two desks, two JSON files, one dispatcher.

Create lec10_vibe/ with tools/hours.json and tools/menu.json plus mcp_server.py.

hours.json: weekday hours 8:00–16:00, closed Sunday, closed campus holidays.

menu.json: weekday drinks, and a "Sunday maple latte brunch special" that implies the cart is serving Sunday.

mcp_server.py must load those files and implement list_tools() and call_tool(name, arguments). Tools:

- get_cart_hours(day) → hours / closed
- get_menu(day) → items for that day

Unknown tool names return {"error": "..."} not a made-up menu. Print list_tools() when run as main. Do not hard-code answers in the orchestrator later — the server reads the JSON.
Check: Running the server prints two tools with names, descriptions, and input schemas. Calling get_cart_hours with day=Sunday says closed. Calling get_menu with day=Sunday still lists the brunch special.

Step 2 Catalog dump 8–13 min

Prove the tools exist before you let the LLM touch them.

Add a --out-dir flag. When I run python mcp_server.py --out-dir output, write output/tool_catalog.json from list_tools() and output/sample_hours.json plus output/sample_menu.json from one real call_tool each (weekday is fine for the samples).
Check: Three JSON files exist. Catalog includes schemas. Samples include tool, arguments, and result.

Step 3 Orchestrator loop 13–23 min

The agent imports MCP. It does not copy the JSON.

Create orchestrator.py and prompts/orchestrator.md.

orchestrator.py takes --query and --out-dir. It imports list_tools and call_tool from mcp_server.py. It calls an LLM in a loop: observe query + prior tool results, decide next tool or finish, execute call_tool, append a trace. Cap at 6 steps.

Write output/orchestrator_sample.json with keys query, answer, action (answer or refuse), tool_trace (list of {name, arguments, result_summary}), conflict {detected, summary}.

Sample query must need BOTH tools, e.g. "I can only come Sunday — is the maple latte still happening?"
Check: Sample JSON has at least two different tool names in tool_trace. The file imported MCP instead of duplicating hours/menu logic.

Step 4 Refuse on disagreement 23–32 min

Sunday is the planted clash: hours say closed, menu advertises brunch.

Update prompts/orchestrator.md: if two tools disagree, set action to refuse, answer to empty or a one-line "I need a human to confirm," conflict.detected true, and summarize the clash. Do not invent a blended policy like "open just for lattes." Re-run the Sunday maple-latte query and overwrite orchestrator_sample.json.
Check: Sunday query → action is refuse and conflict.detected is true. Weekday “are you open at 10 and do you have coffee?” still answers.

Step 5 Mini eval 32–37 min

Two cases, one clash, one clean.

Create cases.json with two objects: weekday_coffee (expect_conflict false) and sunday_brunch (expect_conflict true). Create run_tasks.py that runs the orchestrator on each and writes output/task_eval.json with id, query, action, conflict_detected, expect_conflict, matched_expect_conflict, tools_used.
Check: matched_expect_conflict is true for both rows. Sunday refuses. Weekday answers.

Step 6 AI_prompts.md 37–40 min

Log what you actually typed.

Add a Lecture 10 section to AI_prompts.md with the prompts you used, in your own words, plus one sentence on what broke after the first orchestrator run.
Check: Lecture 10 section exists with at least four prompt summaries.

Stretch (after 40): Draw a one-page HTML block diagram of mcp_server → orchestrator → task_eval, and mark the LLM box and the refuse path. This is practice for HW5 Problem 7, not a substitute for it.
