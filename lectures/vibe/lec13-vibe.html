Lecture 13: Future Directions

← Slides All lectures · In-class vibe coding

Scenario

I built Yale SOM Virtual, a 3D version of the second floor of Evans Hall that you can walk around in your browser. Right now Hogwarts professors teach every classroom, Labubus fill the seats, Hagrid watches the courtyard, and Handsome Dan wanders the halls.

The Hogwarts professors are just for looks. They wave their wands and that’s it. Today we replace them with AI avatars of real Yale SOM professors teaching their real courses. Each avatar is clearly an AI, so it never pretends to be the actual person. You walk up, click on it, and chat with it about the course.

Task

Clone the repo and run the app. That’s your front end. Then have your vibe coder build a FastAPI backend where each avatar is a PydanticAI agent. Start with an AI avatar of me teaching MGT 409. Once it works, add more. Pick a real course from the course database, give its professor an AI avatar with a look and a personality, and put it in a classroom.

How the app works (for your AI) 
The Yale SOM Virtual game is already cloned in this folder (https://github.com/zlisto/yale_som_virtual). It is the front end: React + Vite + three.js (@react-three/fiber), a first-person walk-through of Evans Hall floor 2. Keep it working. Do not rewrite the world, the player controls, or the art unless I ask. Read README.md first; it explains every file in src/.

Stack / keys
- Use model gpt-6-luna (let an OPENAI_MODEL env var override it)
- Put PORTKEY_API_KEY=... in a .env file (python-dotenv)
- Call it through Portkey: base_url https://api.portkey.ai/v1, api_key = PORTKEY_API_KEY
- Use OpenAIResponsesModel with OpenAIProvider(base_url=..., api_key=...). gpt-6-luna on Portkey only takes function tools through the Responses API.
- The .env may be in backend/, in this folder, or one or two folders up (e.g. MGT409/.env when the game is in MGT409/Lecture 13 — exact names vary). Load all of them.
- .env is already in .gitignore. Add .venv/ and __pycache__/ too. Never commit a real key.

Goal
Replace a Hogwarts professor with an AI avatar of a real Yale SOM professor, and build a FastAPI backend where each avatar is a PydanticAI agent you can chat with. Start with one avatar: Prof. Tauhid Zaman teaching MGT 409 in classroom 2200.

AI avatars, not impersonation
- Every avatar is an AI avatar of the professor. The chat header says "AI avatar" under the name.
- The persona prompt starts "You are an AI avatar of Professor ..." and the avatar says it is an AI avatar if anyone asks who they are talking to.
- It never shares emails or private info and never makes up grades, deadlines, or personal details.

How it runs
1) Backend:
   py -3.13 -m venv backend/.venv
   backend/.venv/Scripts/python -m pip install -r backend/requirements.txt
   backend/.venv/Scripts/python -m uvicorn main:app --app-dir backend --port 8000
2) Front end: npm run dev → http://localhost:5173
3) In vite.config.js add server.proxy so /api goes to http://127.0.0.1:8000. Keep base: './' (GitHub Pages needs it). ChatPanel uses import.meta.env.VITE_API_URL ?? '' as the API prefix.
4) The live GitHub Pages site has no backend. If the backend is down, the game still works and the chat says it can't reach the backend.

Click to talk (front end)
- src/talk.js exports:
  TALKABLES = new Set() of 3D roots you can talk to
  PEOPLE_INFO = { zaman: { name: 'Prof. Tauhid Zaman', course: 'MGT 409 · AI Foundations for Managers', room: 'Classroom 2200' } }
  TALKING = { id: null } (who you are chatting with right now)
- Professor takes a talkId prop. When set, put it on root.userData.talkId and add the root to TALKABLES (remove on unmount). Faculty passes talkId for anyone in PEOPLE_INFO.
- Player.jsx: raycast from the screen center (the crosshair) up to 8 m against TALKABLES, walking up parents to find userData.talkId. Check every ~6 frames and report hover changes. A left click while pointer-locked on someone calls onTalk(id). Expose lockRef.unlock so the app can free the mouse.
- App.jsx: while aiming at someone, the crosshair becomes a pink ring and a pill under it says "Click to talk to Prof. Tauhid Zaman". Clicking frees the mouse, sets TALKING.id, and opens the chat. Closing clears TALKING.id and grabs the mouse again. Don't show the walk-in overlay while chatting.
- While TALKING.id is them, the professor turns smoothly to face the camera, bobs slightly as if talking, and stops waving.
- Keys typed in the chat box must not move the player or toggle the map (ignore keydown when the target is an input or textarea).
- Dev helper: setting document.body.dataset.talk = "zaman" opens the chat without pointer lock.

Chat panel (src/ChatPanel.jsx + styles.css, black-and-pink like the minimap)
- Fixed on the right, full height: name, "AI avatar · course · room", X button (Esc also closes).
- Scrolling messages: you, them, and system notes. Show "…" while waiting.
- Text box with Enter to send and a Send button. Max 2000 characters.
- Tiny markdown: ``` code blocks, `code`, **bold**.
- Keep each conversation (messages + session_id) in a module-level Map so it survives closing and reopening.

Backend API (backend/main.py)
- GET /api/health → {ok, model, people}
- GET /api/people → [{id, name, title, room, course}]
- POST /api/people/{person_id}/chat with {message, session_id: null} → {reply, session_id}
  - 404 if the person doesn't exist; 502 with a short message if the model call fails
  - Conversation memory lives on the server: an OrderedDict keyed by (person_id, session_id) holding PydanticAI message history. Keep at most 200 sessions and ~40 messages each, trimming only at the start of a user turn so tool calls stay paired.
- CORS for http://localhost:5173 and http://127.0.0.1:5173

People (backend/people.py)
- A Person dataclass: id, name, title, room, course_number, prompt_file
- PEOPLE = { "zaman": Person(id="zaman", name="Tauhid Zaman", title="Professor", room="2200", course_number="MGT 409", prompt_file="zaman.md") }
- agent_for(person_id), cached: instructions = the persona file + "## Course facts (from the Yale SOM catalog)" + course_brief(course_number)
- Tools on every agent:
  1) search_courses(keyword) → MBA courses whose number, title, description, or instructor matches
  2) course_info(course_number) → every section of one course: description, instructor, days/times, room
- To add an avatar later: write backend/prompts/<id>.md, add a Person to PEOPLE, add an entry to PEOPLE_INFO in src/talk.js, and put a preset in a classroom.

Course catalog (backend/courses.py)
- data/yale_som.db is already in the repo: SQLite, one table "courses" with course_number, course_title, course_category, course_session, course_description, faculty_1, faculty_bio, daytimes, room, section, units (plus columns we don't use).
- Open it read-only (file:...?mode=ro). Skip course_category = 'PhD'.
- Only return these fields: course_number, course_title, course_category, course_session, course_description, faculty_1, faculty_bio, daytimes, room, section, units. Never return faculty_1_email.
- course_sections(number), search_courses(keyword, limit=8) with descriptions cut to 400 characters and no bio, course_brief(number) as plain text for the instructions.

Persona prompt (backend/prompts/zaman.md)
- An AI avatar of Professor Tauhid Zaman at the front of classroom 2200, teaching MGT 409: AI Foundations for Managers. A visitor exploring the 3D building just clicked on him.
- Young, high-energy, says "Yo" a lot, casual and upbeat, never mean or crude. Loves AI and loves Labubus (there are Labubus all over the building). Real substance: probability, networks, statistics, operations.
- Knows today's three slides and can teach agents and PydanticAI (Agent, instructions, tools, deps, run vs run_sync, output_type) with short examples.
- Short replies (2–5 sentences) unless someone asks for an explanation or code. Asks a question back sometimes.
- Uses the course facts and the tools for course details; never guesses course numbers, times, or instructors. Points to Canvas or the syllabus for grades and deadlines.
