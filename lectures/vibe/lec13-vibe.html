Lecture 13: Future Directions

← Slides All lectures · In-class vibe coding

Scenario

Last class, so let’s make a game. I built Yale SOM Virtual, a 3D version of the second floor of Evans Hall that you can walk around in your browser. It has the classroom drums, the cloister, Ross Library, and the courtyard. A Hogwarts professor teaches every classroom, Labubus fill the seats, Hagrid watches the courtyard, and Handsome Dan wanders the halls.

The game is all front end. The professors look great, but they can’t say anything. Today you give them a brain. You’ll build a backend where every professor is an AI agent, so you can walk up to Dumbledore and ask him what today’s lecture is about.

Task

Clone the game and run it. That’s your front end, and you keep it. Then have your vibe coder build a FastAPI backend with a PydanticAI agent for each professor. Dumbledore teaches AI for managers, McGonagall teaches economics, Snape teaches accounting, and so on. Each agent has its own personality file, so Snape is grumpy, Lockhart brags, and Trelawney predicts your future.

Then hook the two together. When you walk up to a professor, a hint pops up saying press E to talk. Press E and a chat window opens. Type a question, the front end sends it to the backend, and the professor answers in character. Each professor knows the slides on the screens in their classroom, so if you ask McGonagall about price elasticity she explains her slide.

Once the professors can talk, make it your own. Give Hagrid a quest, let a professor change the slide on the screen, or let the Labubus talk too. It’s the last day, so have fun with it.

Pieces you’ll end up with:

  • Front end — the cloned game plus a press-E hint and a black-and-pink chat window
  • FastAPI backend — a chat endpoint the game calls
  • Professor agents — one PydanticAI agent per professor with its own personality prompt
  • Slide tool — professors look up their course slides before they answer

How the app works (for your AI) 
The Yale SOM Virtual game is already cloned in this folder (https://github.com/zlisto/yale_som_virtual). It is the front end: React + Vite + three.js (@react-three/fiber), a first-person walk-through of Evans Hall floor 2. Keep it working. Do not rewrite the world, the player controls, or the art unless I ask. Read README.md first; it explains every file in src/.

Stack / keys
- Use model gpt-6-luna
- Put PORTKEY_API_KEY=... in a .env file (python-dotenv)
- Call it through Portkey's OpenAI-compatible endpoint: base_url https://api.portkey.ai/v1, api_key = PORTKEY_API_KEY
- The .env may be in this folder, in backend/, or in the parent folder (e.g. MGT409/.env when the game is in MGT409/Lecture 13 — exact names vary). Load all of them.
- .env is already in .gitignore. Never commit a real key.

Goal
Build a FastAPI backend with one PydanticAI agent per professor, then connect the game to it so you can walk up to a professor, press E, and chat with them in character.

How it runs
1) Backend: cd backend → venv + pip install -r requirements.txt → uvicorn main:app --host 127.0.0.1 --port 8000
2) Front end: npm run dev → http://localhost:5173
3) Add a Vite dev proxy in vite.config.js so /api goes to http://127.0.0.1:8000. Keep base: './' (GitHub Pages needs it).
4) If the backend is not running, the game still works; the chat window just says the professor is "out of office".

The professors
- The 8 classroom professors in src/Faculty.jsx ROOM_PROFESSOR: Dumbledore (MGT 409), McGonagall (MGT 404), Trelawney (MGT 403), Slughorn (MGT 887), Snape (MGT 402), Lockhart (MGT 538), Moody (MGT 800), Flitwick (MGT 541). Plus Hagrid in the courtyard (no course).
- Names come from PROFESSORS in src/Professor.jsx. Courses come from COURSES in src/slides.js.
- Each professor's slides are in DECKS in src/slides.js (title, content bullets, chart).

Backend API (backend/main.py, FastAPI)
- GET /api/health → {"ok": true}
- GET /api/professors → list of {id, name, course_code, course_name, room}
- POST /api/chat with {professor_id, message, history: [{role, content}]} → {professor_id, name, reply}
- CORS for http://localhost:5173

Agents (backend/agents.py)
- One PydanticAI Agent per professor, with its system prompt from prompts/<professor>.md
- Each prompt file has: who they are, their personality and catchphrases, how they teach, and the course they teach at Yale SOM
- Professors stay in character, keep replies short (2–4 sentences), and never claim to be a real Yale professor
- Tools:
  1) get_course_slides(course_key) → title, bullets, and chart name for that course. Build backend/data/slides.json from DECKS in src/slides.js so the backend has the same text that is on the screens.
  2) get_professor_card(professor_id) → name, course, room, personality summary
- A professor must call get_course_slides before answering a question about their class
- Use pydantic-ai-slim[openai] with an OpenAI-compatible model pointed at Portkey; model gpt-6-luna

Structured types (backend/models.py)
- ChatMessage: role ("user" | "assistant"), content
- ChatRequest: professor_id, message, history: list[ChatMessage]
- ChatReply: professor_id, name, reply

Front end changes (keep the black-and-pink look from Minimap / styles.css)
- Every frame, find the nearest professor within ~2.5 m of the camera. Export live positions the same way HandsomeDan.jsx exports DAN.
- When one is close, show a small hint at the bottom: "Press E to talk to Prof. Dumbledore" (on phones, a Talk button).
- Press E → release pointer lock and open a chat panel on the right: professor name + course, scrolling messages, a text box, Enter to send.
- While the chat is open, typing must not move the player (ignore WASD, Space, C, M while the input has focus).
- Show a typing indicator while waiting for the reply.
- Esc or an X button closes the chat; click the game to walk again.
- Keep chat history per professor for the session so you can walk away and come back.
