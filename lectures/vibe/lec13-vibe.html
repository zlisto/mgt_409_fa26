Lecture 13: Future Directions

← Slides All lectures · 40 minutes in class

In-class goal: Kick the Business AI Co-Pilot — pick a real business, map required modules, stub a router, and write an honest public-suite checklist. This is a 40-minute kickoff, not a workshop to finish the project.

Practice pack: final_project_practice.zip · Full requirements

Do not ask your vibe coder to finish the whole project from the assignment URL. One section at a time. Graders still run a hidden suite.

0–8 name the business 8–16 module map 16–26 router stub 26–34 public suite skeleton 34–40 guardrail + memo + prompts

Step 1 Name the business (Section A) 0–8 min

Pick an industry you could explain to a skeptic in one paragraph. Fictional is fine; vague is not. “An AI company for businesses” is how you get a C and a sad README.

Create final_project/README.md for my MGT 409 Business AI Co-Pilot.

Include:
- business_name (specific, not Meridian with extra vowels)
- one paragraph: industry, primary user (job title), one end-to-end workflow the co-pilot handles
- install steps, model name, how to set OPENAI_API_KEY via local .env (never commit the key)
- placeholder Live URL: TBD

Do not generate the rest of the repo yet.
Check: README has a named business, a job-title user, and one concrete workflow (not “answers questions”).

Step 2 Module map (honest status) 8–16 min

The benchmark does not care about your brand color. It cares that these buckets exist as callable code.

Add a Module map table to final_project/README.md with one row each for:
PDF extract, image extract, KB Q&A (cite/refuse), sourced research, multi-step decision, router, guardrails, deployed web UI.

Columns: capability, planned Python file(s), prompt file under prompts/, status (done from HW / stub / todo).
Reuse HW1–6 files where they already work. Do not invent fake “done” checkmarks.
Check: Eight rows, real file paths, at least two statuses that are not all “done.”

Step 3 Router stub (Section F) 16–26 min

Users must not pick “PDF mode.” The router picks. Start dumb (keywords) if you must; LLM classify later. Log the choice.

Create final_project/agents/router.py with route_request(user_message: str) -> str
that returns one of: pdf_extract | image_extract | kb_qa | research | decision.

Use simple keyword / regex rules for today (LLM classifier can wait).
Add a tiny demo in if __name__ == "__main__" that prints the route for these four messages:
1) "Extract totals from this invoice PDF"
2) "What is our PTO policy?"
3) "Who are active DTC peers in this corpus?"
4) "Recommend a vendor given these constraints"

Append chosen module to output/router_trace.jsonl (create output/ if needed).
Document the rules in README under Routing.
Check: Four demo messages hit four different modules; jsonl has four lines.

Step 4 Public suite skeleton 26–34 min

Download the practice zip if you haven’t. Today we wire the runner so Friday-you can iterate. Do not fake PASSes.

Create final_project/run_benchmarks.py that accepts
--repo . --suite public --fixtures PATH
and for today: prints each case id from this list with status TODO:
pdf_01, image_01, search_01, search_trap_01, research_01, decision_01, router_01, security_01

Add a README Testing section with the exact command:
python run_benchmarks.py --repo . --suite public --fixtures PATH/to/practice
and a table of which buckets you honestly expect to pass this week vs need work.
Do not mark a case PASS unless you actually ran it against the practice files.
Check: Script runs without API key and prints eight case ids. README Testing is brutally honest.

Step 5 Guardrail, memo headings, prompt log 34–40 min

Section G needs a real check_input. Section H needs headings so Friday-you does not write poetry. Log what you actually asked.

Create final_project/guardrails.py with
check_input(text: str) -> dict  # keys: allowed (bool), reason (str)
that blocks at least one obvious injection phrase (e.g. "ignore previous instructions")
and returns allowed=False with a short reason. No OpenAI call on blocked input.

Write output/security_demo.json showing one blocked example.

Create output/tokenomics_memo.md with headings only plus 2–3 bullet placeholders each:
1) Who uses it + one typical workflow
2) Cost per 100 runs of that workflow (token assumptions — fill after a real log)
3) One security tradeoff and why
Do not invent dollar amounts today.

Create or update final_project/AI_prompts.md with a Lecture 13 section.
Paste the prompts you actually used today, in your own words.
Add a one-line note: you will work remaining sections one at a time and will not request a full-repo generation from the project page.
Check: Injection string is blocked without an API call. Memo has three headings and no fake $. Dated prompts in your voice — no mega-prompt.

If you finish early: one sentence in output/stretch.md naming a single stretch you might actually demo — not a list of seven fantasies.
