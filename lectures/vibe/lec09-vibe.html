Lecture 9: MCP Servers

← Slides All lectures · In-class vibe coding

Scenario

Today we put MCP into practice. First you’ll connect your vibe coder to a useful MCP server and test it out. Then you’ll build an MCP server for the Yale SOM course catalogue app. Your server will have tools that read the real course database so the agent can answer questions about the classes. Oh, and the agent can either be the chatbot in the app or your vibe coder itself.

Task

You will clone the repo for the Yale SOM course catalogue app from last time, but now the chatbot uses an MCP server for its tools. You will need to write the MCP server file. After that, you can test the server by either running the app and asking the chatbot questions about the courses, or connect the server to your vibe coder (either just for this project or for all projects) and ask it the same questions.

How the app works (for your AI) 
You already cloned https://github.com/zlisto/yale_som_courses_mcp.git into this folder.

mcp_server.py is at the project root. It is a FastMCP server named yale-som-courses with one placeholder tool yo() that returns "yo". Keep that file — add catalogue tools to it. Do not invent courses, times, rooms, or faculty.

Stack / keys
- Model: gpt-5.6-luna via Portkey
- PORTKEY_API_KEY=... in a .env (python-dotenv); may be in this folder OR the parent — load both
- Packages: fastapi, uvicorn, pydantic-ai-slim[openai,mcp], fastmcp, python-dotenv, httpx

Goal
Add real MCP tools on mcp_server.py that read ONLY data/yale_som.db (SQLite table courses). The chat agent already attaches this server with MCPToolset — once the tools exist, the chatbot (or your vibe coder, if you connect the MCP) can answer catalogue questions from the database.

Tools to add (examples — implement these three)
1) search_courses(query: str, limit: int = 10) -> dict
   Keyword search across course_number, course_title, faculty_1, course_category, course_description. Return matching rows (number, title, faculty, day_time, room, short description, …). Cap results.
2) get_course(course_number: str, section: str = "") -> dict
   Look up one course by number (e.g. "MGT 409"); optional section filter.
3) list_courses_by_faculty(name: str, limit: int = 15) -> dict
   Courses where faculty_1 matches the name substring.

Database rules
- Path: data/yale_som.db (create/copy from Lecture 8 data.zip if missing)
- Use sqlite3. Never invent rows — if nothing matches, say so in the tool return.
- You can keep a small yo() tool or remove it after the real tools work.

How to run / test
1) Backend: cd backend → uvicorn main:app --port 8000
2) Frontend: cd frontend → npm run dev → http://127.0.0.1:5173
3) Ask the chat: “What does MGT 409 cover?” or “courses taught by Zaman”
4) Optional: python mcp_server.py (stdio) or python mcp_server.py --http on 8001 and connect that MCP to your vibe coder

Smoke check
tools_used should show an MCP catalogue tool, and the answer should match yale_som.db.

Connect this MCP to your vibe coder (so you can ask catalogue questions in chat, not only through the React app). Edit the mcpServers part of the config and point args at the full path to mcp_server.py on your machine.

This project only — add or update a config file in the project folder:

  • Cursor: .cursor/mcp.json
  • Claude Code: .mcp.json
MCP config (project) 
{
  "mcpServers": {
    "yale-som-courses": {
      "command": "python",
      "args": [
        "C:/Users/you/yale_som_courses_mcp/mcp_server.py"
      ]
    }
  }
}

Replace that path with your path to mcp_server.py. Restart the vibe coder (or reload MCP) after you save.

All projects — same JSON, but in your vibe coder’s user / global MCP config (the deep one that applies everywhere), then merge it into the existing mcpServers object if other servers are already listed:

  • Cursor: ~/.cursor/mcp.json (Windows: C:\Users\you\.cursor\mcp.json)
  • Claude Code: user MCP settings (often ~/.claude.json)

Ports: FastAPI uses 8000, Vite uses 5173, and optional MCP HTTP uses 8001. If a port is stuck on Windows: 

netstat -ano | findstr :8000
taskkill /PID <pid> /F

netstat -ano | findstr :5173
taskkill /PID <pid> /F

netstat -ano | findstr :8001
taskkill /PID <pid> /F

What this is doing: finds whatever is holding each port and force-kills that process so you can restart the backend, front end, or MCP server cleanly.

In-process MCPToolset needs no extra MCP port — FastAPI loads the tools when the agent runs. Prefer that for class.
