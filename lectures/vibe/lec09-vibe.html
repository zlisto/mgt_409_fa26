Lecture 9: MCP Servers

← Slides All lectures · In-class vibe coding

Scenario

Today we put MCP into practice. First you’ll connect your vibe coder to a useful MCP server and test it out. Then you’ll build an MCP server for the Yale SOM course catalogue app. Your server will have tools that read the real course database so the agent can answer questions about the classes. Oh, and the agent can either be the chatbot in the app or your vibe coder itself.

Task

You will clone the repo for the Yale SOM course catalogue app from last time, but now the chatbot uses an MCP server for its tools. You will need to write the MCP server file. After that, you can test the server by either running the app and asking the chatbot questions about the courses, or connect the server to your vibe coder (either just for this project or for all projects) and ask it the same questions.

Software Details

Clone the following repo: https://github.com/zlisto/yale_som_courses_mcp

Clone starter 
git clone https://github.com/zlisto/yale_som_courses_mcp.git

Have your vibe coder install the backend and front end packages.

The starter already includes mcp/mcp_server.py (its own folder + requirements.txt), but it only has a placeholder tool (yo). In class you’ll add real catalogue tools that read data/yale_som.db. The web app imports that MCP in-process — you don’t run a second MCP terminal for the chatbot. For your vibe coder, make a venv inside mcp/ and point the MCP config at that Python + mcp_server.py.

Then give your vibe coder this prompt:

How the app works (for your AI) 
You already cloned https://github.com/zlisto/yale_som_courses_mcp.git into this folder.

mcp/mcp_server.py is a FastMCP server named yale-som-courses with a placeholder tool yo() that returns "yo". Keep that file — add catalogue tools to it. Do not invent courses, times, rooms, or faculty.

Stack / keys
- Model: gpt-5.6-luna via Portkey
- PORTKEY_API_KEY=... in a .env (python-dotenv); may be in this folder OR the parent — load both
- Backend packages: fastapi, uvicorn, pydantic-ai-slim[openai,mcp], fastmcp, python-dotenv, httpx (backend/requirements.txt)
- MCP packages: fastmcp (mcp/requirements.txt) — make mcp/.venv for vibe-coder stdio

Goal
Add real MCP tools on mcp/mcp_server.py that read ONLY data/yale_som.db (SQLite table courses). The chat agent already attaches this server with MCPToolset in-process — you do NOT need to run mcp_server.py in a second terminal for the web app. Once the tools exist, the chatbot (or your vibe coder, if you connect the MCP) can answer catalogue questions from the database.

Tools to add (examples — implement these three)
1) search_courses(query: str, limit: int = 10) -> dict
   Keyword search across course_number, course_title, faculty_1, course_category, course_description. Return matching rows (number, title, faculty, day_time, room, short description, …). Cap results.
2) get_course(course_number: str, section: str = "") -> dict
   Look up one course by number (e.g. "MGT 409"); optional section filter.
3) list_courses_by_faculty(name: str, limit: int = 15) -> dict
   Courses where faculty_1 matches the name substring.

Database rules
- Path: data/yale_som.db relative to the project root (create/copy from Lecture 8 data.zip if missing)
- In mcp_server.py, DB path should be ROOT / "data" / "yale_som.db" (parent of the mcp/ folder)
- Use sqlite3. Never invent rows — if nothing matches, say so in the tool return.
- You can keep a small yo() tool or remove it after the real tools work.

How to run / test
1) Backend: cd backend → uvicorn main:app --port 8000  (imports mcp/ — no separate MCP process)
2) Frontend: cd frontend → npm run dev → http://127.0.0.1:5173
3) Ask the chat: “What does MGT 409 cover?” or “courses taught by Zaman”
4) Optional vibe-coder connect: cd mcp → venv + pip install -r requirements.txt; point MCP config at mcp/.venv Python and mcp/mcp_server.py

Smoke check
tools_used should show an MCP catalogue tool, and the answer should match yale_som.db.

Connect this MCP to your vibe coder. First set up a Python venv and install the required packages inside the mcp/ folder (ask your vibe coder to do this). This makes it so the vibe coder can launch the server in a self-contained, portable manner. Then edit the mcpServers part of the config and point command at that venv’s Python and args at mcp_server.py (ask your vibe coder to do this as well). Next, you connect the vibe coder to the MCP server. You can do this for this project only, or for all of your projects. Ask your vibe coder to help you with this.

This project only — add or update a local config file in the project folder:

  • Claude Code: .mcp.json
  • Cursor: .cursor/mcp.json
  • Codex (VS Code / IDE plugin): .codex/config.toml in the project (or use the Codex panel gear → MCP servers → Add server)
MCP config (project — Claude / Cursor JSON) 
{
  "mcpServers": {
    "yale-som-courses": {
      "command": "C:/Users/you/yale_som_courses_mcp/mcp/.venv/Scripts/python.exe",
      "args": [
        "C:/Users/you/yale_som_courses_mcp/mcp/mcp_server.py"
      ]
    }
  }
}
MCP config (project — Codex TOML) 
[mcp_servers.yale-som-courses]
command = "C:/Users/you/yale_som_courses_mcp/mcp/.venv/Scripts/python.exe"
args = ["C:/Users/you/yale_som_courses_mcp/mcp/mcp_server.py"]

Use your paths. Prefer the mcp/.venv Python so fastmcp is installed. Restart the vibe coder (or reload / restart the Codex extension) after you save.

All projects — same settings, but in your vibe coder’s user / global MCP config (the deep one that applies everywhere). For JSON tools, merge into the existing mcpServers object if other servers are already listed:

  • Claude Code: user MCP settings (often ~/.claude.json)
  • Cursor: ~/.cursor/mcp.json (Windows: C:\Users\you\.cursor\mcp.json)
  • Codex (VS Code / IDE plugin): ~/.codex/config.toml (Windows: C:\Users\you\.codex\config.toml) — same TOML block as above
MCP config (global — merge into mcpServers) 
"yale-som-courses": {
  "command": "C:/Users/you/yale_som_courses_mcp/mcp/.venv/Scripts/python.exe",
  "args": [
    "C:/Users/you/yale_som_courses_mcp/mcp/mcp_server.py"
  ]
}

Codex tip: the VS Code Codex panel and the Codex CLI share the same config.toml. You can also run codex mcp add yale-som-courses -- C:/Users/you/yale_som_courses_mcp/mcp/.venv/Scripts/python.exe C:/Users/you/yale_som_courses_mcp/mcp/mcp_server.py (use your real paths).
