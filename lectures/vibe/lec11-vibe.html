Lecture 11: Tokenomics

← Slides All lectures · In-class vibe coding

Scenario

Last class you built a Harry Potter multi-agent chat app — React front end, FastAPI back end, PydanticAI agents, and a book database. Today we keep that desk and add tracking of its token spend in dollars.

Agents are cheap until they aren’t. You want to see the bill while the boss and book specialists work, pick a cheaper or smarter model, and cut the run off if spend gets too high.

Task

Start by cloning the repo for this lecture (it already has a working multi-agent app). Your job is to add a cost meter that tracks dollar spend as the agents work — for each agent and for the whole job.

After a run, show input tokens, output tokens, and cached / cache-write tokens when the API gives them, plus the dollar cost. Put thermometer-style meters on the dashboard so you can watch spend climb live. Add a model picker for gpt-6-luna and gpt-6-astra, and a budget box that stops the agents when spending hits your limit. Cache each agent’s stable system prompt so repeat calls can use cheaper cached tokens.

Pieces you’ll end up with:

  • Pricing helper — turn token counts into dollars using OpenAI rates
  • Live spend events — backend pushes spend updates while agents run
  • Thermometer meters — boss, each book agent, and total dollars
  • Model + budget controls — choose luna/astra; optional hard USD cap
  • Prompt caching — cache stable agent instructions on the Responses API

Goal
Keep the Harry Potter multi-agent chat working. While the boss and book specialists run, track token usage (input, output, cache read, cache write), convert to USD with OpenAI Standard short-context prices, show live thermometer meters per agent + total, let the user pick luna vs astra, and stop the whole job if spend hits an optional USD budget. Also cache each agent’s stable system prompt so repeat calls can use cheaper cached tokens.

OpenAI Standard short-context prices (USD per 1M tokens)
Source: https://developers.openai.com/api/docs/pricing
- gpt-6-luna: input $0.10 · cached $0.01 · cache write $0.125 · output $0.50
- gpt-6-astra: input $10.00 · cached $1.00 · cache write $12.50 · output $50.00
Treat input_tokens as inclusive of cache_read_tokens + cache_write_tokens (bill uncached = input − cache_read − cache_write at the input rate).

What to build

1) backend/agents/pricing.py
- MODEL_PRICES for luna and astra
- cost_usd(model, usage) and enrich_usage(model, usage) adding cost_usd
- BudgetExceeded exception when spend >= budget

2) backend usage plumbing
- In agents/events.py usage_dict, capture cache_read_tokens and cache_write_tokens when present
- Track spend per agent key: "boss" and "book-1" … "book-7"
- Emit a "spend" SSE event whenever usage updates (model, budget_usd, total_usd, agents, total)
- ChatRequest gains model and optional budget_usd
- Pass model + budget through /api/chat and /api/chat/stream
- If total spend hits budget_usd, stop the run (raise BudgetExceeded / cancel further model calls) and return an error/final payload that still includes usage + any specialist reports so far
- GET /api/pricing returns the price table + source URL

3) Prompt caching (Responses API)
- Cache the stable system / developer instructions for the boss and for each book specialist
- Put the long unchanged prompt first; mark a prompt_cache_breakpoint after the stable prefix
- Keep per-question evidence / user text after the breakpoint so it stays uncached
- Do not invent a fake cache — use the Responses API cache fields and surface cache_read_tokens / cache_write_tokens in usage when the API returns them

4) frontend
- Model dropdown: gpt-6-luna | gpt-6-astra
- Optional Budget USD number input (blank = no cap)
- Send model + budget_usd on /api/chat/stream
- Live thermometer meters for Total, Boss, and each Book agent (fill vs budget if set, else a sensible dynamic scale)
- Listen for "spend" events to update meters without flooding the ops log
- Final answer usage line should show dollars + token breakdown (input / cached / cache write / output)
- Keep markdown table rendering for final answers working (remark-gfm + any jam-fix you already have)

How to run / test
1) Backend: cd backend → venv + pip install -r requirements.txt → uvicorn main:app --reload --host 127.0.0.1 --port 8000
2) Frontend: cd frontend → npm install → npm run dev → http://127.0.0.1:5173 (proxies /api to 8000)
3) Ask a cross-book question (Horcruxes). Watch meters move. Try a tiny budget (e.g. 0.001) and confirm the run stops. Switch luna ↔ astra and confirm the price legend changes.
