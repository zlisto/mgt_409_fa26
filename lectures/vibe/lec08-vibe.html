Lecture 8: Application Deployment

← Slides All lectures · In-class vibe coding

Scenario

Open the Yale SOM course explorer you built in Lecture 7. Today we’re updating that same app: swap the JSON file for a real database, add user login, save each person’s chat history, and put the whole thing online so someone else can open a URL and use it.

Download data.zip and unzip next to your project so you get data/yale_som.db. It already has a courses table with the SOM course catalog (same info that used to live in the JSON). You’ll add users and chats tables as you build.

Task

Keep the React + FastAPI + PydanticAI shape you already have. The catalog grid can still show courses — just load them from the database. The chat agent’s course search tool should query the courses table instead of reading the JSON file. Add a login / create-account screen in front of the app. After someone signs in, their chat messages get saved so they can come back to them. When it works on your laptop, push the code to GitHub, move the database to Supabase, and deploy on Render.

Software Details

Work through these pieces with your vibe coder:

  • Add users and chats tables to the database (keep the existing courses table)
  • Redo the class search tool so it searches the courses table instead of the JSON
  • Store passwords with bcrypt (salt is baked into the hash string)
  • Push the project to a GitHub repo
  • Put the database on Supabase and point the app at it with the connection string
  • Deploy on Render — one Web Service (backend) and one Static Site (frontend); deploy the backend first so you have its URL for the frontend
  • In Render’s environment variables, set PORTKEY_API_KEY and your Supabase connection string (never put those in the repo)
