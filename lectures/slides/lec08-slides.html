Application Deployment

Tauhid Zaman

Putting Apps Online

  • We can build full-stack apps — a front end people click, a back end that answers
  • Next step: put them online so other people can open a URL and use them
  • You’ll need a few things to do that:
    • Git and a GitHub account — so the host can pull your code
    • A hosting platform — a company that runs your app on the public internet (this usually costs money)

What Is Git?

  • Git turns a folder into a repository — a project with version history
  • It tracks every change you make to files in that folder (the green/red diffs on the right)
  • Snapshots are called commits — you can go back if something breaks
  • A hidden .git folder marks this folder as a repo and stores the commits that track your project’s history

What Is GitHub?

  • GitHub is the website that hosts your code repositories online
  • Typical flow: create an empty repo on GitHub, then push your local project up so it lives online
  • You can also clone someone else’s repo — download a copy to your laptop and start from their code

Databases

  • A database stores many tables
  • Tables store structured rows — users, messages, product information
  • Your app queries the database for information
  • Local database file for class today

Local Databases

  • Local database files end in .db, e.g. mgt409.db
  • Perfect for prototypes — the data sits in a file on your laptop, right next to your code
  • sqlite3 — Python module that lets you interact with databases

Online Databases

  • Supabase — an online database host for your app
  • Same idea as a local .db — tables and queries — living on the internet so a hosted app can reach it
  • Site: https://supabase.com/

Setting Up Supabase

  1. Make a project
  2. Create a database in the project — also create a database password and put it in your .env file
  3. Get the connection string (you’ll insert your password into it) and put it in your code
  4. Use your vibe coder to add tables and data
  5. You can also have your vibe coder connect to the Supabase MCP server (covered in a later lecture)

User Logins

  • Add logins to protect your app — and to monetize it (paid accounts, subscriptions)
  • User info lives in a table in your database
  • Passwords must be hashed — turned into scrambled one-way text before you store them

Good Password Practice

  • Use a slow hash built for passwords — bcrypt or PBKDF2
    • Slow on purpose: guessing stolen hashes one-by-one takes forever
  • Add a salt — a random string mixed into the password before hashing, so two people with the same password still get different hashes
    • In bcrypt, the salt is stored inside the password hash string — login reads it from there

Beyond A Password

  • 2FA / MFA — second factor (phone app, SMS, hardware key)
  • OAuth “Sign in with Google” style logins
  • Email password reset tokens, lockouts after failed logins

Putting Apps Online

  • Once your app is working, the next step is to put it online
  • Typical path: push code to a GitHub repo → connect a hosting service to the repo → hosting service puts the app online
  • Secrets (API keys) go in the host’s secure env settings

Render

  • Easy to use hosting service — connect a GitHub repo and deploy
  • Site: https://render.com/
  • Can run front end, back end, and workers
  • Typical costs
    • About $7/month for a web service (backend)
    • Front end static site is free

Deploying Full Stack App On Render

  • One GitHub repo → two Render services
  • Deploy backend first, then front end — you need the backend URL for the front end

1. Backend — Web Service

  1. Root directory: backend/
  2. Build: pip install -r requirements.txt
  3. Start: uvicorn main:app --host 0.0.0.0 --port $PORT
  4. Env vars in Render (not in git): PORTKEY_API_KEY, SUPABASE_DB_URL, …
  5. You get a URL like https://your-backend.onrender.com

2. Frontend — Static Site

  1. Root directory: frontend/
  2. Build: npm install && npm run build
  3. Publish directory: dist
  4. Build env: VITE_API_URL=https://your-backend.onrender.com
  5. You get a URL like https://your-frontend.onrender.com

Other Hosting Services

  • Lovable — strong for spinning up front ends quickly
  • AWS / Azure / Google Cloud — full cloud platforms (more knobs)
  • Pick based on what you’re shipping — UI-only vs full API + workers

Hosting Websites On GitHub

  • GitHub can host a static website for free (HTML / CSS / JS — no backend)
  • Put an index.html in your repo and turn on GitHub Pages in the repo settings
  • Your site URL looks like https://yourusername.github.io/your-repo/
  • This class website is hosted that way: https://zlisto.github.io/mgt_409_fa26/
